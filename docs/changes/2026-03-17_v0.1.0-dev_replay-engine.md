## Summary

Implemented the complete Replay Engine for PetalTrace (Phase 6). This enables replaying workflow runs in three modes: live (re-execute against real LLM providers), mocked (use captured responses for deterministic replay), and hybrid (mock tools but make live LLM calls). The engine includes request validation, auto-diff capability, CLI commands, and REST API endpoints.

## Motivation

The Replay Engine enables:
1. Debugging by re-executing problematic runs with different configurations
2. A/B testing prompt changes by comparing original vs. modified runs
3. Deterministic testing with mocked responses
4. Cost-free iteration with mocked LLM calls
5. Regression testing workflows after changes
6. Testing prompt modifications while keeping tool behavior constant (hybrid mode)

## What Changed

### New Additions

**replay/request.go** — Request handling and validation
- `ReplayRequest` struct with mode, overrides, tags, auto-diff flag
- `ReplayOverrides` for model, temperature, max_tokens, provider, graph, input changes
- `ReplayMode` enum: live, mocked, hybrid
- `ReplayStatus` enum: pending, running, completed, failed
- `Replay` struct tracking replay state
- `RequestValidator` validates requests and loads source run data
- `CapturedData` holds run, spans, LLM spans, tool spans
- `ApplyOverrides` merges configuration changes

**replay/live.go** — Live replay mode
- `LiveReplayer` executes against real LLM providers
- `ExecuteRequest` sent to PetalFlow daemon API
- `Replay` method triggers execution via `/api/execute`
- `WaitForCompletion` polls for async completion
- Sets `parent_run_id` for lineage tracking

**replay/mocked.go** — Mocked replay mode
- `MockedReplayer` uses captured responses
- `MockProvider` maps node IDs to captured LLM responses
- `CapturedLLMResponse` and `CapturedToolResult` types
- `BuildMockProvider` extracts responses from source run
- `executeMocked` creates new run with copied spans
- Deterministic execution, no actual LLM calls

**replay/hybrid.go** — Hybrid replay mode
- `HybridReplayer` mocks tools, makes live LLM calls
- `HybridExecuteRequest` extends execute request with mocked tools
- `ToolMockMode` controls which tools are mocked
- `ExtractToolMocks` extracts tool outputs for mocking
- Useful for testing prompt changes with consistent tool behavior

**replay/engine.go** — Orchestration
- `Engine` orchestrates all replay modes
- `Execute` starts async replay
- `ExecuteSync` waits for completion
- `performAutoDiff` computes diff after completion
- `GetReplay`, `ListReplays`, `GetReplaysBySourceRun` for tracking
- `RefreshReplayStatus` updates status from store

**cmd/petaltrace/replay.go** — CLI command
- `petaltrace replay <run_id>` — replay a run
- `--mode live|mocked|hybrid` — replay mode
- `--model`, `--provider`, `--temperature`, `--max-tokens` — overrides
- `--diff` — auto-diff after completion
- `--sync` — wait for completion (default true)
- `--tag key=value` — add tags to new run
- `--json` — output as JSON
- `replay status <replay_id>` — check status
- `replay diff <replay_id>` — compute diff for completed replay

**api/replay.go** — REST API endpoints
- `POST /api/replay` — trigger replay
- `GET /api/replay/{id}` — get replay status
- `GET /api/replays` — list replays (optionally by source_run_id)

## Technical Specification

### Replay Modes

| Mode | LLM Calls | Tool Calls | Use Case |
|------|-----------|------------|----------|
| live | Real | Real | Re-execute with different config |
| mocked | Captured | Captured | Deterministic testing, cost-free |
| hybrid | Real | Captured | Test prompt changes |

### Data Types

```go
// ReplayRequest defines a replay operation
type ReplayRequest struct {
    SourceRunID string            `json:"source_run_id"`
    Mode        ReplayMode        `json:"mode"`
    Overrides   ReplayOverrides   `json:"overrides,omitempty"`
    Tags        map[string]string `json:"tags,omitempty"`
    AutoDiff    bool              `json:"auto_diff,omitempty"`
}

// ReplayOverrides contains configuration overrides
type ReplayOverrides struct {
    Model          string          `json:"model,omitempty"`
    Temperature    *float64        `json:"temperature,omitempty"`
    MaxTokens      *int            `json:"max_tokens,omitempty"`
    Provider       string          `json:"provider,omitempty"`
    GraphOverrides json.RawMessage `json:"graph_overrides,omitempty"`
    InputOverrides json.RawMessage `json:"input_overrides,omitempty"`
}

// Replay represents an in-progress or completed replay
type Replay struct {
    ID          string       `json:"id"`
    SourceRunID string       `json:"source_run_id"`
    NewRunID    string       `json:"new_run_id,omitempty"`
    DiffID      string       `json:"diff_id,omitempty"`
    Mode        ReplayMode   `json:"mode"`
    Status      ReplayStatus `json:"status"`
    Error       string       `json:"error,omitempty"`
    StartedAt   time.Time    `json:"started_at"`
    CompletedAt *time.Time   `json:"completed_at,omitempty"`
}
```

### CLI Interface

```
petaltrace replay <run_id> [flags]

Flags:
  --mode string           Replay mode: live, mocked, or hybrid (default "live")
  --model string          Override LLM model
  --provider string       Override LLM provider
  --temperature float     Override sampling temperature
  --max-tokens int        Override max tokens
  --diff                  Auto-diff after completion
  --sync                  Wait for replay to complete (default true)
  --tag strings           Add tags (format: key=value)
  --json                  Output as JSON
  --petalflow-url string  PetalFlow daemon URL (default "http://localhost:8080")

Subcommands:
  status <replay_id>     Check replay status
  diff <replay_id>       Compute diff for completed replay
```


## Integration Notes

The Replay Engine integrates with:

1. **PetalFlow Daemon** — Live and hybrid modes send execution requests to PetalFlow's `/api/execute` endpoint
2. **Store** — Creates new runs and spans, updates aggregates
3. **Diff Engine** — Auto-diff feature computes comparison after completion
4. **Lineage Tracking** — New runs have `parent_run_id` set to source run

For mocked mode, no external dependencies are required — the engine creates a complete copy of the run with preserved span data.
