## Summary

Implemented the complete PetalTrace CLI with commands for starting the daemon, managing workflow runs, viewing prompts and completions, analyzing costs, exporting/importing runs, garbage collection, and displaying storage statistics.

## Motivation

PetalTrace requires a command-line interface for operators and developers to interact with the observability platform. The CLI provides essential functionality for starting the daemon, querying trace data, analyzing costs, and managing storage without needing the web UI.

## What Changed

### New Additions

#### Serve Command (`cmd/petaltrace/serve.go`)
```go
var serveCmd = &cobra.Command{
    Use:   "serve",
    Short: "Start the PetalTrace daemon",
    RunE:  runServe,
}
```

Starts the PetalTrace daemon with:
- Configuration loading from `petaltrace.yaml`
- SQLite store initialization with migrations
- OTLP collector startup (HTTP on 4318, gRPC on 4317)
- Pricing table loading
- Graceful shutdown on SIGINT/SIGTERM

## Technical Specification

### CLI Interface

#### petaltrace serve
```bash
petaltrace serve [--config <path>]
```

Starts the daemon, loading configuration and initializing:
- SQLite store at configured path
- OTLP HTTP receiver on port 4318
- OTLP gRPC receiver on port 4317
- Pricing table (builtin or with overrides)

#### petaltrace runs list
```bash
petaltrace runs list [flags]

Flags:
  --workflow string   Filter by workflow name
  --status string     Filter by status (running, completed, failed)
  --since string      Show runs since duration (e.g., 24h, 7d)
  --limit int         Maximum number of runs to show (default 50)
  --json              Output as JSON
```

Output:
```
STATUS  WORKFLOW            RUN ID              DURATION  TOKENS  COST      STARTED
✓       email-processor     run-abc12345678...  1.2s      5000    $0.0150   2026-03-17 10:15:30

Showing 1 runs
```

#### petaltrace runs show
```bash
petaltrace runs show <run-id> [flags]

Flags:
  --spans          Show span tree
  --node string    Filter spans by node ID
  --json           Output as JSON
```

#### petaltrace prompt
```bash
petaltrace prompt <run-id> <node-id> [flags]

Flags:
  -c, --completion     Include the completion/response
  -f, --format string  Output format: text, json, curl, sdk (default "text")
```

SDK output generates Python code for Anthropic or OpenAI based on provider.

## Usage Examples

### Starting the Daemon
```bash
# Start with default config
petaltrace serve

# Start with custom config
petaltrace serve --config /etc/petaltrace/petaltrace.yaml
```

### Listing and Viewing Runs
```bash
# List recent runs
petaltrace runs list

# List completed runs from the last 24 hours
petaltrace runs list --status completed --since 24h

# Show run details with span tree
petaltrace runs show run-abc123 --spans

# Output as JSON for scripting
petaltrace runs list --json | jq '.[] | select(.workflow_name == "my-workflow")'
```

### Viewing Prompts
```bash
# Show prompt for an LLM node
petaltrace prompt run-abc123 llm-node-1

# Include completion
petaltrace prompt run-abc123 llm-node-1 --completion

# Generate cURL command
petaltrace prompt run-abc123 llm-node-1 --format curl

# Generate Python SDK code
petaltrace prompt run-abc123 llm-node-1 --format sdk
```

### Cost Analysis
```bash
# Summary for last 7 days
petaltrace cost summary

# Summary grouped by provider
petaltrace cost summary --group-by provider

# Per-run breakdown by node
petaltrace cost run run-abc123 --by-node
```

### Export/Import
```bash
# Export a run
petaltrace export run-abc123 my-run.json

# Import with new IDs (to avoid conflicts)
petaltrace import my-run.json --new-id
```

### Garbage Collection
```bash
# Preview what would be deleted
petaltrace gc --dry-run

# Run GC with custom retention
petaltrace gc --retain 14d

# Run GC including starred runs
petaltrace gc --include-starred
```

## Integration Notes

**CLI integrates with:**
- **Store**: All commands use `openStore()` to connect to SQLite
- **Config**: Commands load configuration from `petaltrace.yaml`
- **Collector**: The `serve` command starts the OTLP collector
- **Pricing**: Cost calculations use the pricing system

**Downstream Components:**
- The HTTP API (Phase 4) will provide the same functionality via REST
- The UI (Phase 8) will visualize the same data the CLI queries
