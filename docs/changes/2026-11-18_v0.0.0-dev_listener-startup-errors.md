## Summary

API and OTLP bind failures are now returned synchronously from startup. The collector binds both OTLP listeners before starting its receivers, so it cannot report success when either configured port is unavailable.

## Motivation

Previously, the API started `ListenAndServe` in a goroutine and the collector started both receivers in goroutines. Bind failures were only logged asynchronously, while `petaltrace serve` continued to log readiness.

## What Changed

### New Additions

- Added `TestServer_StartReturnsBindError`.
- Added `TestCollector_StartReturnsHTTPBindError` and `TestCollector_StartReturnsGRPCBindError`. The gRPC failure test also verifies that the already-bound HTTP listener is released.

### Modifications

- `api.Server.Start` calls `net.Listen` and returns any bind error before starting the serving goroutine.
- OTLP receivers separate loopback validation/listening from serving so the collector can bind both endpoints first.
- `Collector.Start` returns an HTTP or gRPC bind error synchronously. If the second listener fails, the first listener is closed and the collector resets its startup state.
- `runServe` defers collector shutdown after successful startup, so an API bind failure also stops the collector and flushes its writer.
- `petaltrace serve` already returns collector/API startup errors before logging readiness; these errors now reach that path.
- Stop methods close listeners even if the serving goroutine has not begun accepting connections yet.

## Usage Examples

### Example: Listener port is occupied

When the API port or either OTLP port cannot be bound, startup returns a contextual `listen` error and the command exits before logging `petaltrace ready`.

## Integration Notes

The startup path still starts the API only after both OTLP listeners bind successfully. PetalFlow, Iris, and Cortex integration contracts are unchanged.

## Breaking Changes & Migration

None. A port conflict that previously allowed a partially started daemon now causes startup to fail.

## Deferred / Out of Scope

This change handles listener bind failures. Errors that occur later while a server is serving remain logged by the background serving goroutine.
