## Summary

`petaltrace gc` now treats `retention.default: never` as disabled retention and exits without deleting runs. It no longer replaces the zero duration used for `never` with a 30-day fallback.

## Motivation

The duration parser maps `never` to zero. The GC command previously treated zero as an omitted setting and substituted 30 days, which could delete unstarred runs despite an explicit no-expiration policy.

## What Changed

### New Additions

- Added `TestRunGCNeverRetentionPreservesOldRuns`, which exercises dry-run and normal GC against an old persisted run with `retention.default: never`.

### Modifications

- `runGC` no longer replaces a zero retention duration with 30 days.
- When retention is zero, `runGC` reports `Retention period: never` and `No runs to delete.`, then exits before opening the store.
- An omitted `retention.default` still uses the configured 30-day default.

### Removals

- Removed the fallback that interpreted an explicit `never` duration as 30 days.

### CLI Interface

The `gc` command and flags are unchanged. With `retention.default: never`, the command reports no deletions and does not open the store.

N/A. No exported Go APIs changed.

### Configuration

- `retention.default`: existing duration field; `never` remains represented as zero duration and now disables GC. If omitted, the configured default remains `30d`.

## Usage Examples

### Example: Disable run expiration

```yaml
retention:
  default: never
```

Running `petaltrace gc` reports `Retention period: never` and `No runs to delete.` The same no-op applies with `--dry-run`.

None. This corrects behavior to match the existing `never` configuration value.
