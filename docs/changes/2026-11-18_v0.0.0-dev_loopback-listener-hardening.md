## Summary

PetalTrace now binds its unauthenticated HTTP API and OTLP receivers to loopback by default and rejects non-loopback listener addresses. The API no longer grants CORS access to arbitrary origins. Configuration, integration, and CLI documentation now describe the local-only behavior.

## Motivation

The API exposes stored prompts and traces and includes destructive and mutating operations. The OTLP receivers accept writes. Since authentication is not implemented, binding these services to all interfaces exposed sensitive data and operations to the network.

## What Changed

### New Additions

- Added `internal/netutil.IsLoopbackHost(host string) bool` and `internal/netutil.IsLoopbackAddr(addr string) bool` for loopback checks shared by config and listener startup.
- Added tests for loopback host/address recognition and for safe listener defaults, rejection of non-loopback addresses, and absence of wildcard CORS permission.

### Modifications

- `internal/config` defaults `server.host` to `127.0.0.1` and rejects non-loopback hosts.
- `auth.enabled: true` is rejected because authentication is not implemented; setting it does not authorize a public bind.
- API server default address is `127.0.0.1:8090`; `Start` rejects non-loopback addresses.
- OTLP/HTTP and OTLP/gRPC receiver defaults are `127.0.0.1:4318` and `127.0.0.1:4317`. `NewCollector` and direct receiver startup reject non-loopback addresses.
- `runServe` explicitly configures both OTLP listeners on `127.0.0.1`.
- Removed the API middleware that added `Access-Control-Allow-Origin: *`.
- Updated README, configuration, PetalFlow integration, and CLI reference documentation for local-only bindings.

### Removals

- Removed wildcard CORS headers and automatic CORS preflight responses.

## Technical Specification

### Data Schemas / Types

N/A. No persisted data schemas or public request/response shapes changed.

### API Endpoints

N/A. Endpoint paths and methods are unchanged. Cross-origin browser requests are no longer granted access by default.

### CLI Interface

N/A. No CLI commands or flags changed. `petaltrace serve` uses loopback listener addresses.

### Go Package API

Added internal helpers:

```go
func IsLoopbackHost(host string) bool
func IsLoopbackAddr(addr string) bool
```

They return true only for `localhost` or loopback IP hosts with valid host:port syntax for address checks.

### Configuration

- `server.host`: string, defaults to `127.0.0.1`; must be `localhost` or a loopback IP. Non-loopback values are rejected.
- `auth.enabled`: bool, defaults to `false`; setting it to `true` is rejected because authentication is not implemented.
- `collector.otlp_http_port` and `collector.otlp_grpc_port`: existing integer ports remain configurable; receivers bind to loopback only.

## Usage Examples

### Example: Local-only listener configuration

```yaml
server:
  host: "127.0.0.1"
  port: 8090

collector:
  otlp_http_port: 4318
  otlp_grpc_port: 4317
```

The API is available at `http://127.0.0.1:8090`; local OTLP clients can send to `127.0.0.1:4318` or `127.0.0.1:4317`.

### Example: Rejected public bind

```yaml
server:
  host: "0.0.0.0"
```

Configuration validation fails with an error that `server.host` must be loopback because network authentication is not implemented.

## Integration Notes

PetalFlow OTLP export works when PetalFlow and PetalTrace share a host. Remote PetalFlow clients cannot send to the loopback-only receiver. No Iris or Cortex integration behavior changed.

## Breaking Changes & Migration

- Configurations that set `server.host` to a non-loopback address now fail validation.
- Configurations with `auth.enabled: true` now fail validation rather than implying authentication is active.
- Remote OTLP ingestion and cross-origin browser API access are not supported until authenticated network access is implemented.

## Deferred / Out of Scope

Authentication, remote listener configuration, and configurable CORS allowlists remain out of scope. Do not expose PetalTrace through public or container-network interfaces until authentication is implemented.
