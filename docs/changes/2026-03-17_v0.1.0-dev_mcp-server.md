## Summary

Implemented the MCP Server for PetalTrace (Phase 7). This exposes trace query, prompt inspection, cost analysis, diff comparison, and replay capabilities to agents via the MCP protocol. The server uses stdio transport and registers tools under the `petaltrace.*` namespace, enabling self-reflective agent patterns where agents can inspect their own execution history.

## Motivation

The MCP Server enables:
1. Agents querying their own prior runs for self-diagnosis
2. Automated workflow comparison and regression testing
3. Cost monitoring and optimization by AI assistants
4. Prompt inspection for debugging agent behavior
5. Replay triggering for A/B testing and deterministic reproduction
6. Integration with PetalFlow via the overlay file

## What Changed

### New Additions

**mcp/server.go** — MCP server implementation
- `Server` struct with stdio transport
- JSON-RPC 2.0 protocol handling
- `Tool` struct with name, description, schema, and handler
- `Request` and `Response` types for protocol messages
- `handleInitialize` responds with server capabilities
- `handleToolsList` returns registered tools
- `handleToolsCall` invokes tool handlers
- Protocol version: 2024-11-05

**mcp/tools_trace.go** — Trace query tools
- `petaltrace.trace.list` — List recent runs with filters (workflow, status, since, limit)
- `petaltrace.trace.get` — Get run detail with optional span tree
- `petaltrace.trace.search` — Search runs by content in prompts/completions
- `TraceListResult`, `TraceGetResult`, `TraceSearchResult` response types
- `RunSummary`, `RunDetail`, `SpanDetail`, `SearchHit` data types

**mcp/tools_prompt.go** — Prompt and cost tools
- `petaltrace.prompt.get` — Get full prompt/completion for LLM node
- `petaltrace.cost.summary` — Aggregate cost metrics with grouping
- `petaltrace.cost.run` — Per-run cost breakdown by node/provider/model
- `PromptGetResult` with messages, completion, tokens, latency
- `CostSummaryResult` with breakdown and time range
- `CostRunResult` with per-node cost details

**mcp/tools_diff.go** — Diff and replay tools
- `petaltrace.diff.compare` — Compare two runs with structural, content, and cost diffs
- `petaltrace.run.replay` — Trigger replay in live/mocked/hybrid modes
- `DiffCompareResult` with summary, node diffs, and cost diff
- `RunReplayResult` with replay status and new run ID

**mcp/overlay.yaml** — PetalFlow integration overlay
- `group_actions` mapping friendly names to MCP tool names
- `output_schemas` defining response shapes for each tool
- `config` section for endpoint configuration
- `metadata` with author, version, and tags

### Protocol Messages

```go
// Request (JSON-RPC 2.0)
type Request struct {
    JSONRPC string          `json:"jsonrpc"`
    ID      *json.RawMessage `json:"id,omitempty"`
    Method  string          `json:"method"`
    Params  json.RawMessage `json:"params,omitempty"`
}

// Response
type Response struct {
    JSONRPC string          `json:"jsonrpc"`
    ID      *json.RawMessage `json:"id,omitempty"`
    Result  json.RawMessage `json:"result,omitempty"`
    Error   *ErrorObject    `json:"error,omitempty"`
}
```

## Usage Examples

### Example: List recent failed runs

```json
// Request
{"jsonrpc": "2.0", "id": 1, "method": "tools/call", "params": {
    "name": "petaltrace.trace.list",
    "arguments": {"status": "failed", "since": "24h", "limit": 10}
}}

// Response
{"jsonrpc": "2.0", "id": 1, "result": {
    "content": [{"type": "text", "text": "{\"runs\":[...],\"count\":5}"}]
}}
```

### Example: Get prompt for debugging

```json
// Request
{"jsonrpc": "2.0", "id": 2, "method": "tools/call", "params": {
    "name": "petaltrace.prompt.get",
    "arguments": {"run_id": "run-abc123", "node_id": "researcher_agent"}
}}
```

### Example: Compare two runs

```json
// Request
{"jsonrpc": "2.0", "id": 3, "method": "tools/call", "params": {
    "name": "petaltrace.diff.compare",
    "arguments": {
        "base_run_id": "run-v1",
        "compare_run_id": "run-v2",
        "include_content": true
    }
}}
```

### Example: Replay with model override

```json
// Request
{"jsonrpc": "2.0", "id": 4, "method": "tools/call", "params": {
    "name": "petaltrace.run.replay",
    "arguments": {
        "run_id": "run-abc123",
        "mode": "live",
        "model": "claude-3-opus-20240229",
        "auto_diff": true
    }
}}
```

### Example: Self-reflective agent workflow

```yaml
agents:
  diagnostic_agent:
    role: "Workflow Diagnostician"
    goal: "Analyze recent execution failures and recommend improvements"
    tools:
      - petaltrace.trace.list
      - petaltrace.trace.get
      - petaltrace.prompt.get
      - petaltrace.diff.compare

tasks:
  diagnose:
    description: >
      Review the last 5 failed runs of the 'research_pipeline' workflow.
      Identify common failure patterns and suggest prompt or configuration changes.
    agent: diagnostic_agent
    expected_output: "A structured report with failure patterns and recommendations."
```

## Integration Notes

The MCP Server integrates with:

1. **Store** — All tools query the trace store for run and span data
2. **Diff Engine** — `diff.compare` tool uses the diff engine for comparisons
3. **Replay Engine** — `run.replay` tool triggers replay execution
4. **PetalFlow** — The `overlay.yaml` file enables integration with PetalFlow's tool discovery

The MCP server uses stdio transport, making it compatible with:
- Claude Code and other MCP clients
- PetalFlow's MCP adapter
- Any application implementing the MCP protocol
