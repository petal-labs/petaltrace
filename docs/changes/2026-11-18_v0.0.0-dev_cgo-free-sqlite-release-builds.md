## Summary

Replaced the CGO-required SQLite driver with the pure-Go `modernc.org/sqlite` driver, pinned at v1.45.0 for Go 1.24 compatibility. Release builds remain CGO-disabled and now smoke-test database initialization and migrations.

## Motivation

The release and Makefile builds set `CGO_ENABLED=0`, while `github.com/mattn/go-sqlite3` is a CGO-dependent stub in that mode. Binaries compiled successfully but could not open their SQLite database.

## What Changed

### New Additions

- Added `scripts/release-smoke-test.sh <petaltrace-binary>`, which runs the binary's `stats --json` command against a temporary database and verifies the database file was created.
- Added `TestRunMigrationsCopiesLegacyFTS4SearchIndex` to verify migration of existing indexed prompt/completion text to FTS5.
- Added CI smoke tests that build and run a CGO-disabled native artifact on Ubuntu, macOS, and Windows. The release workflow smoke-tests its Linux/amd64 artifact before publishing assets.
- Added `make release-smoke-test`, with `SMOKE_BINARY` defaulting to `bin/petaltrace`.

### Modifications

- Replaced `github.com/mattn/go-sqlite3` with `modernc.org/sqlite v1.45.0`; `NewSQLiteStore` now opens driver name `sqlite`.
- Replaced the initial FTS4 index with an FTS5 index named `spans_fts5`, using the Porter tokenizer.
- Added schema migration v2. For existing v1 databases, migration v2 copies the FTS4 shadow-content rows into FTS5 without requiring the old FTS4 module. The existing FTS4 table is left unused.
- Updated `IndexSpanText` and `SearchSpans` to use FTS5.
- README now notes that the SQLite release build does not require CGO or a C compiler.

### Removals

- Removed the direct `github.com/mattn/go-sqlite3` dependency.

## Technical Specification

### Data Schemas / Types

Schema migration v2 adds:

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS spans_fts5 USING fts5(
    span_id UNINDEXED,
    prompt_text,
    completion_text,
    tokenize='porter'
);
```

Existing v1 databases retain the unused `spans_fts` FTS4 virtual table. Its `spans_fts_content` shadow rows are copied to `spans_fts5` during migration.

## Usage Examples

### Example: Smoke-test a locally built artifact

```bash
make build
make release-smoke-test
```

The command exits successfully only if the binary can initialize SQLite and run migrations. To test a release artifact at a different path:

```bash
make release-smoke-test SMOKE_BINARY=dist/petaltrace-linux-amd64
```

### Example: CGO-disabled verification

```bash
CGO_ENABLED=0 go test ./store
```

## Integration Notes

PetalFlow, Iris, and Cortex integrations are unchanged. The database remains SQLite; only the Go driver and the internal full-text index migration changed.

## Breaking Changes & Migration

None expected. Existing FTS4 prompt/completion index content is copied to FTS5 during schema migration v2. The old FTS4 table is retained but no longer read or written.

## Deferred / Out of Scope

CI builds and smoke-tests native CGO-free binaries for each published OS/architecture. The release workflow cross-compiles all five assets and smoke-tests the Linux/amd64 asset before upload.
