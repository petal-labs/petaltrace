## Summary

Completes PostgreSQL parity for the `TraceStore` operations that were still stubbed with `ErrUnsupportedOperation`: span text indexing/search, pricing reads/writes, diff reads/writes, and retention garbage collection. (Stats and aggregate updates were already implemented in the earlier PostgreSQL backend change.) Every `TraceStore` method now works on both backends, so selecting `storage.driver: postgres` never falls back to SQLite and never returns an unsupported-operation error for interface operations.

## Motivation

GitHub issue #10 ([P1] Complete PostgreSQL parity for search, pricing, diffs, stats, and retention). After the PostgreSQL run/span backend landed (PR #14), the remaining interface methods returned `ErrUnsupportedOperation`, breaking span search, cost pricing overrides, run diffs, and store-level retention deletion for PostgreSQL deployments.

## What Changed

### New Additions

- PostgreSQL migration `2_search_diffs_pricing` in `store/postgres.go`, adding three tables:
  - `span_text (span_id PK → spans ON DELETE CASCADE, prompt_text, completion_text, search_vector tsvector)` with a GIN index (`idx_span_text_search`) — the PostgreSQL counterpart of the SQLite FTS5 `spans_fts5` table.
  - `diffs (id PK, base_run_id FK, compare_run_id FK, diff_data, created_at, UNIQUE(base_run_id, compare_run_id))` with base/compare indexes — mirrors the SQLite `diffs` table.
  - `pricing (provider, model, effective_from composite PK, input_per_1m, output_per_1m, cache_read_per_1m, cache_write_per_1m)` with `idx_pricing_lookup` — mirrors the SQLite `pricing` table.
- `scanPricingRow(row scanner)` helper and a package-private `scanner` interface (`Scan(dest ...any) error`) so `*sql.Row` and `*sql.Rows` share one pricing scan path.

### Modifications

Previously stubbed `PostgresStore` methods now have real implementations that preserve the SQLite backend's behavior and error semantics:

| Method | Implementation |
|---|---|
| `IndexSpanText` | Upserts into `span_text` (`ON CONFLICT (span_id) DO UPDATE`) and recomputes `search_vector = to_tsvector('english', coalesce(prompt,'') \|\| ' ' \|\| coalesce(completion,''))`. Re-indexing a span replaces its text, matching FTS5 behavior. |
| `SearchSpans` | Joins `spans` with `span_text` and matches `search_vector @@ websearch_to_tsquery('english', $1)`, ordered by `started_at DESC` with a `LIMIT` (default 50 when `limit <= 0`, same as SQLite). |
| `CreateDiff` | Inserts into `diffs` with the whole `RunDiff` marshaled as JSON into `diff_data` (identical to SQLite). Duplicate `(base_run_id, compare_run_id)` pairs fail on the UNIQUE constraint, same as SQLite. |
| `GetDiff` / `GetDiffByRuns` | Scan `diff_data` and unmarshal; missing rows return `nil, nil` (same as SQLite). |
| `GetPricing` | Selects the latest `effective_from` for a `(provider, model)`; unknown pairs return `nil, nil`. |
| `UpsertPricing` | `INSERT ... ON CONFLICT (provider, model, effective_from) DO UPDATE` — the PostgreSQL equivalent of SQLite's `INSERT OR REPLACE`. |
| `ListPricing` | Lists all entries ordered by `provider, model, effective_from DESC`. |
| `GarbageCollect` | Counts (dry run) or deletes `runs` where `started_at < cutoff AND starred = 0`, with cutoff computed as `now - retentionDays` UTC. Returns the deleted count. Skips SQLite's `VACUUM` (not applicable to PostgreSQL; autovacuum handles space reclamation). |

### Removals

None. The `ErrUnsupportedOperation` stubs are replaced; the sentinel itself remains exported for other potential backend gaps (no interface method returns it anymore).

## Technical Specification

### Data Schemas / Types

No Go type changes. New PostgreSQL schema (migration version 2):

```sql
CREATE TABLE span_text (
    span_id TEXT PRIMARY KEY REFERENCES spans(id) ON DELETE CASCADE,
    prompt_text TEXT,
    completion_text TEXT,
    search_vector tsvector NOT NULL
);
CREATE INDEX idx_span_text_search ON span_text USING GIN (search_vector);

CREATE TABLE diffs (
    id TEXT PRIMARY KEY,
    base_run_id TEXT NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
    compare_run_id TEXT NOT NULL REFERENCES runs(id) ON DELETE CASCADE,
    diff_data TEXT NOT NULL,
    created_at TEXT NOT NULL,
    UNIQUE (base_run_id, compare_run_id)
);
CREATE INDEX idx_diffs_base ON diffs(base_run_id);
CREATE INDEX idx_diffs_compare ON diffs(compare_run_id);

CREATE TABLE pricing (
    provider TEXT NOT NULL,
    model TEXT NOT NULL,
    input_per_1m DOUBLE PRECISION NOT NULL,
    output_per_1m DOUBLE PRECISION NOT NULL,
    cache_read_per_1m DOUBLE PRECISION,
    cache_write_per_1m DOUBLE PRECISION,
    effective_from TEXT NOT NULL,
    PRIMARY KEY (provider, model, effective_from)
);
CREATE INDEX idx_pricing_lookup ON pricing(provider, model);
```

Timestamps remain RFC3339Nano UTC strings (`formatTime`), consistent with the rest of the PostgreSQL schema.

### API Endpoints

N/A — daemon API unchanged. Endpoints backed by these store methods (e.g., span search, diffs, pricing) now work unchanged when the server is configured with PostgreSQL.

### CLI Interface

N/A — CLI unchanged. `petaltrace export` span-text indexing and the diff/pricing commands now function against PostgreSQL without changes.

### Go Package API

No exported signatures changed. All `store.TraceStore` methods are now fully implemented by both `*SQLiteStore` and `*PostgresStore`.

### Configuration

N/A — `storage.driver: postgres` + `storage.postgres.dsn` behave as before; no new fields.

## Usage Examples

### Example: full-text search on PostgreSQL

```go
traceStore, _ := store.NewStore(ctx, store.StoreOptions{
    Driver:   "postgres",
    Postgres: store.PostgresOptions{DSN: dsn},
})

_ = traceStore.IndexSpanText(ctx, spanID, "retry payment invoice processing", "charge the customer card")
spans, _ := traceStore.SearchSpans(ctx, "payment", 10) // matches prompt or completion tokens
```

### Example: pricing override and retention

```go
_ = traceStore.UpsertPricing(ctx, &store.PricingEntry{
    Provider: "anthropic", Model: "claude-3-5-sonnet",
    InputPer1M: 3, OutputPer1M: 15,
    EffectiveFrom: time.Now().UTC(),
})
entry, _ := traceStore.GetPricing(ctx, "anthropic", "claude-3-5-sonnet")

deleted, _ := traceStore.GarbageCollect(ctx, 30, false) // deletes unstarred runs older than 30 days
```

## Integration Notes

- `websearch_to_tsquery` provides token-and-phrase matching close to SQLite FTS5 `MATCH`; exotic FTS5 query operators (prefix `term*`) are not interpreted, they are treated as plain text. Document-level semantics (AND across terms, quoted phrases) match.
- `span_text` cascades on span deletion, so `DeleteRun`/`GarbageCollect` automatically remove indexed text for deleted spans — verified by test.
- No command falls back to SQLite when PostgreSQL is selected: `store.NewStore` dispatches strictly by `storage.driver`, and every interface method is now implemented for PostgreSQL.
- SQLite migrations/tests are untouched; existing SQLite behavior is unchanged.

## Breaking Changes & Migration

- Existing PostgreSQL databases migrate automatically on store open (migration 2 runs inside a transaction and is recorded in `schema_migrations`).
- Code that previously handled `ErrUnsupportedOperation` from PostgreSQL stores (e.g., tests asserting search returned the sentinel) will no longer see that error; those operations now succeed. No public API breaks.

## Deferred / Out of Scope

- Exposing tsvector ranking/relevance ordering or SQLite-style FTS5 prefix queries; current parity target is behavioral compatibility, not feature parity beyond it.
- Postgres-native `UPDATE ... FROM`-style single-statement `UpdateRunAggregates` (the existing span-tree-based implementation is retained).
