## Summary

PetalTrace can now select PostgreSQL through `storage.driver` and persist/read runs and spans there. CLI, daemon, seed, and MCP startup use a shared store factory, so a PostgreSQL DSN is no longer silently ignored in favor of SQLite.

## Motivation

Configuration already accepted `storage.driver: postgres` and `storage.postgres.dsn`, but every command instantiated SQLite directly. PostgreSQL settings therefore did not select the configured database.

## What Changed

### New Additions

- Added `store.NewStore(ctx, StoreOptions) (TraceStore, error)` to select SQLite or PostgreSQL.
- Added `store.PostgresStore`, backed by `github.com/jackc/pgx/v5/stdlib` v5.8.0.
- Added PostgreSQL schema migration v1 for runs and spans, including indices and run-to-span cascade deletion.
- Added `TestPostgresStoreRunSpanLifecycle`; CI runs it against a PostgreSQL 16 service.
- Added `TestOpenStoreDoesNotFallBackToSQLiteForPostgresConfig`.

### Modifications

- Routed `serve`, `mcp`, `seed`, and shared CLI store access through `store.NewStore`.
- `petaltrace stats` now reports the selected storage driver for PostgreSQL without displaying the SQLite path.
- PostgreSQL implements run/span create, get, update, delete, list/pagination, batch span writes, run aggregate updates, and storage health/statistics.
- SQLite remains the default backend and retains its existing implementation.
- `ErrUnsupportedOperation` identifies store operations not yet implemented by PostgreSQL.

### Removals

N/A. SQLite support remains available.

## Technical Specification

### Data Schemas / Types

PostgreSQL migration v1 creates `schema_migrations`, `runs`, and `spans` tables, with indices for workflow, status, time, parent, trace, and starred-run queries. Span rows reference runs with `ON DELETE CASCADE`. Snapshot, tag, and typed span payload fields are stored as text-encoded JSON, matching the existing model serialization.

### API Endpoints

N/A. Endpoint shapes are unchanged. Endpoints that require store operations outside this issue’s scope return an explicit unsupported-operation error when PostgreSQL is selected.

### CLI Interface

No command or flag signatures changed. Commands that use the shared factory now open the configured backend. SQLite remains the default.

### Go Package API

```go
type StoreOptions struct {
    Driver   string
    SQLite   SQLiteOptions
    Postgres PostgresOptions
}

func NewStore(ctx context.Context, opts StoreOptions) (TraceStore, error)

type PostgresOptions struct {
    DSN string
}

var ErrUnsupportedOperation = errors.New("operation is not supported by the selected storage backend")
```

`NewStore` selects the requested backend and returns an error for unsupported drivers or connection/migration failures; it does not fall back to SQLite.

### Configuration

- `storage.driver`: `sqlite` by default; accepts `postgres`.
- `storage.postgres.dsn`: required for the PostgreSQL driver.
- Environment variables: `PETALTRACE_STORAGE_DRIVER` and `PETALTRACE_STORAGE_POSTGRES_DSN`.

## Usage Examples

### Example: PostgreSQL run/span storage

```yaml
storage:
  driver: postgres
  postgres:
    dsn: "postgres://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require"
```

Do not commit credentials. To provide the DSN from the environment:

```bash
export PETALTRACE_STORAGE_DRIVER=postgres
export PETALTRACE_STORAGE_POSTGRES_DSN='postgres://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require'
petaltrace serve
```

### Example: Unsupported PostgreSQL operation

PostgreSQL full-text search is not included in this storage slice. A call to the store search operation returns `store.ErrUnsupportedOperation` rather than using a separate SQLite database.

## Integration Notes

PetalFlow OTLP ingestion and run/span storage can use PostgreSQL through `petaltrace serve`. No Iris or Cortex integration behavior changed. PostgreSQL full-text search, pricing persistence, diffs, and store-level garbage collection remain follow-up work.

## Breaking Changes & Migration

Previously, PostgreSQL configurations could silently open SQLite. They now use the configured PostgreSQL DSN. Operators who relied on that accidental fallback must set `storage.driver: sqlite` and configure `storage.sqlite.path` to continue using SQLite.

## Deferred / Out of Scope

PostgreSQL search/FTS, diff persistence, pricing persistence, and store-level garbage collection are out of scope for this slice and tracked separately.
